## 4. 工作纪律（血泪教训，务必遵守）

1. **门禁必须串行**：判官共用 `_t/work`，并行会读出假数据（踩过两次，读出过“130/328”）。用 `gate.py`，不要手工并行。
2. **只在门禁表全绿**时才宣布“提升”；**blind29/30 才是泛化读数**，26–28 是调过的。
3. **停止逐关键词调优**（结论见 §6.859–§6.877）：泛词（`的和`/`最大值`/`第二`）几乎必然抢别的题。
   - 反例：`排除 第二` 把“第二行是 N 个整数”的题全打掉（hidden 323/328）。
   - 要加词就必须**配精确排除**，并同一轮跑 `gate.py`。
4. **改动攒批**，门禁全绿后再统一推送发布（用户明确要求“不要推太频繁”）。
5. **负结果必须写进文档**（`阶段四-验收.md` 的 §9.x + `audit` 的 §6.xxx），否则下一轮会重复踩。
6. 改知识后**必须重建模型**：`sh code/build_code_model.sh`（否则判官用旧模型，读数骗人）。
