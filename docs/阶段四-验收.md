## 六、已知边界（照实说，别再重复问）

1. **能力 = 知识**：图里没有的任务/片段/模板，一条也写不出来（C1 就是这条的证据）。
2. **检索是子串匹配**：关键词没有词边界、没有否定处理 ——「不要写素数」也会命中素数。
3. **组合是线性拼接**：片段顺序靠"依赖排序"（§6.708：子串判据 + 冒泡松弛），
   模板永远第一、主体永远最后；片段 >16 个会**静默丢**多余的（没报错）。
   依赖判据只认"代码里出现另一个片段的名字"：注释/字符串会误判成依赖，
   改名调用/函数指针会漏判；成环时放弃排序。
4. **单文件、只有 C11**：多文件工程、别的语言都不在范围内（`::code build` 能编多文件，但合成只到单文件）。
5. **消融只做了"删代码边"**：全删（C1）与只删片段（C2）；"删关键词边""换错骨架""删模板"没做。
6. **真知识 10⁶ 边已经能到（§6.709：1 261 334 边），但性能不达标**：载入 3.08 s / RSS 1.40 GB /
   存盘 4.35 s，三条都超 M3 目标 ⇒ 默认仍是 406 125 边的公共 API 版。要拿它当默认，
   先做阶段三 M2-3「边打包 + 字符串池」。**§6.702 那句"真知识上不了 10⁶ 边"是错的**
   （真原因：`INC` 只扫了 `/usr/include`，全机有 59 527 个 `.h`）。
7. **`.c` 片段知识已进图（§6.710），但合成器还不会自动用**：图里从 3 个手写片段涨到 **1 124 个**
   真实函数体（298 个"独立"），但 `::code synth` 的组合仍靠 `任务 --用--> 片段` 的**手写边**
   ⇒ B 段一条都没变（15/15 是"没被弄坏"，不是"变好"）。自动检索片段是下一步。
8. **两侧单条查询延迟没在 10⁶ 边上量**（只量了载入/存盘/RSS 和 B 段通过率）。

## 七、0.5B 边（5×10⁸）：分片语料 + 局部加载（§6.706）

### 结论先说

**0.5B 不是"一张图全装进内存"，而是 25 个 2000 万边的分片落盘（28 GB），每次只激活一片。**
依据：全装需 ≈91 GB（182 B/边实测），本机 15 GB —— 差 8 倍，单文件全装在本机不可能。

### 实测数字（全部可复现）

| 项 | 数值 | 怎么量的 |
|---|---|---|
| 分片总量 | **25 片 × 20 000 205 边 ≈ 5.0×10⁸ 边** | `::stats` 数了 shard_01 与 shard_25 |
| 总落盘 | **28 GB** | `du -sh /mnt/models/aip-corpus-0.5B/big` |
| 单片 | 400 449 词 / 20M 边 / 模型 1.10 GB | `ls -l` + `::stats` |
| parts 打包 | **每片 1 个文件**（1.2 GB，400 079 段） | `::parts save` + `find \| wc -l` |
| parts save | 2M 边 7.3 s（20M 边约 90 s 量级） | `/usr/bin/time` |
| **attach（只挂索引）** | **0.10 s / RSS 15 MB** | `/usr/bin/time` |
| detach | 65 510 个词的边离开内存，查询时按需读回 | `::parts detach` + `::rel` 能答出 |
| 跨片正确性 | 同词 `w000001`：A 片给出 w020170/w020171，B 片给出 w063709/w063710 | 两片分别 attach 后 `::rel` |

### 负结果（必须照实写）

- **`detach` 不降低"峰值 RSS"**：仅加载 3 632 160 KB，attach+detach+查询 3 632 324 KB —— 峰值出现在加载阶段（建 20M 条边），detach 发生在之后。所以"内存降 90%"这种说法是**错的**；能说的是"边可以换到磁盘、按需读回"。
- **`attach` 只挂索引，不合并语料**：在只有 1271 词的 `model.bin` 里 attach 一个 40 万词的分片，查 `w000001` 会答"不在图里"、`::parts stats` 显示"读回 0 段"——因为那个模型里没有这个 token，也就没有可解析的哨兵。`::parts` 的语义是"**同一张图的边外置**"，不是"跨语料合并"。
- **跨片 = 换片**：要做"一张 0.5B 的单图"必须新做分片命名空间 + 索引合并（路线 B），本轮没做。

### 一句话

**分片路线（路线 A）已经打通并验证**：单片 3.63 GB 峰值、索引 attach 0.1 s/15 MB、边按需读回、跨片答案随激活片变化。**路线 B（跨片单图）未做**，需要新功能。

## 九、7B 边分片语料（§6.711；用户 2026-11-03 追加目标）

**是什么**：7 000 000 000 条边、**350 片 × 2000 万边**、每片一个 `.c7b` 文件（**8 B/边**），
合计 **58.2 GB**；挂上一片只读 48 字节头，查一个词按需读那一段（实测 512 字节）。

**为什么换格式**：0.5B 那批每片是完整模型（**59.2 B/边**）、`::parts` 是 **64.4 B/边**
⇒ 7B 要 414 / 451 GB，而 `/mnt/models` 只剩 327 GB。`.c7b` 只存边（邻居 + 关系）⇒ 58 GB。

**怎么用**：`::parts corpus <片.c7b>` / `::parts corpus rel w000042` / `::parts corpus stats`。

**证据**：`tests/corpus7b.sh`（9 项：确定性、每片自洽、段内无重复、断点续跑、引擎可挂可查、
坏文件拒）；`tools/gen_corpus7b.sh --verify-only` 重算总边数；清单 `manifest.txt` 记每片边数/字节。
**边界**：不是一张单图（350 次独立抽样、无跨片边）；引擎只接了 `::parts corpus` 这一条读法
（`::rel`/求解器还没接）；7B 全是**合成边**，不是知识。详见 `docs/7B-边语料.md`。

### 9.7 内存构成实测（为什么 RSS 还差 180 MB）

用 `mallinfo2` + 逐项统计（`AIP_LOADDBG`，测量代码已撤，不留调试侵入）：

| 项 | 大小 |
|---|---|
| Token 结构 | 658 893 × 320 B ≈ **201 MB** |
| AssocEntry（sumcap 2 197 544 × 72 B） | ≈ **150 MB** |
| 名字 | ≈ **18 MB** |
| 反查表 rev（1 077 067 × 12 B） | ≈ **12 MB** |
| NameEntry + 桶 | ≈ **34 MB** |
| **每词一份 emb（658 893 × 1 024 B）** | **≈ 674 MB** ← 主因 |
| 其它（AI 层、关系表、槽类、idf…） | 余下 |

结论：**RSS 的 60% 是每词一份的 1 KB emb**，它在 `pool_token` 里 `calloc(EMB_DIM)` 就分配了，
即使 `emb_deferred` 把**计算**推迟了，**内存**也没省。

要把 RSS 压到 ≤1 GB，下一步是**emb 惰性分配**：创建词时不分配，`ai_embed_build` 时统一建；
风险点是 42 处 `->emb` 读取里少数没有判空（`ai.h:3244/3335` 是构建路径，`5127/5141/5143`
是相似度路径），要先逐处加空判据或共享零向量，再跑整包 + `conc_tsan`。

存盘/载入时间侧的下一步仍是：边先编码进栈缓冲一次性写入（减少每字段函数调用）、
以及 `cap` 精确分配（当前 1 条边的词也占 4 条边的内存，约 100 MB）。

### 9.33 迁移检验：自学能学会自己的家族，但**迁移 = 0**（2026-11-13）

这轮加了两个开关并做了两个关键测量：

|---|---|---|
| blind19 | 7 通过 / 1 拒绝 | **7 / 1**（不变）|
| blind20 | 8 / 0 | **8 / 0**（不变）|
| blind21 | 1 / 4 / 3 答错 | **1 / 4 / 3**（不变）|

**结论：自学 11→25/27 的能力，对没见过的题迁移为零**。因为它学的是“整句关键词 → 语句”的对应，
而不是“最大值”这种**概念**——换个说法就认不出。

**② 泛化尝试（`--generalize`）**：把起草出来的整句关键词砍成短词（去掉 `输出/所有元素/矩阵` 前缀），

```

  能力门：FAIL（回滚泛化）
```

——短关键词立刻把旧题抢乱（能力门当场抓到并回滚）。所以“靠砍关键词来迁移”这条路是**堵死**的，
不是一个可以绕过的实现细节。

**下一步（写进计划）**：要迁移，得把学到的知识从“整句关键词”升级成**带类型的算子**
（`类别:数组 × 操作:取最大 → 结果:int`），让描述匹配发生在“概念层”而不是“字符串层”。
这是结构改动，不是再加几条三元组。


### 9.34 概念层关键词（模式匹配）：一条知识吃一族说法（2026-11-13）

### 9.35 按你设计的那条路训练：需求 → 拆解/图内推 → 断点 → 取源 → 验证 → 扩图（2026-11-13）

实现了 `tools/selfserve.py` + `tests/selfserve.sh`（§6.822），就是你说的那条流水线：

```

  → ① 图内推（::code synth）  成功 ⇒ 四层验证（示例/性质/稳定/换说法）
  → ② 断点分类：没匹配 / 没编过 / 测试不过（读 note）
  → ③ 取源：产品联网（::net on + ::web search；白名单内）→ 失败则读本地语料 _t/serve/corpus/*.c
```

**实测（4 条需求，全部带示例）**：

| 需求 | 训练前 | 结果 |
|---|---|---|
| 正约数个数 | 没匹配（被 最大公约数 抢） | **LEARN**（采纳语料里的正确实现）|

**训练前 0/4 ⇒ 训练后 4/4，入库 4 条**。

**最关键的一条证据**：语料里我放了一份**错误实现**（约数个数漏掉自己，返回 5 而不是 6），
验证层当场 `REJECT … 示例 12 得到 '5' 期望 '6'` —— 说明“没有 Python 参考实现、只有示例+性质”
也能判语义错。这是第二个问题（语义正确性无 oracle）的第一个可运行答案。

**边界照实说**：

- 产品联网这条是**白名单 + 不跟重定向**（`::net get` 对 runoob 返回 301 就放弃），所以真实网页取源
  需要部署侧把域名加进 `net/allow.txt` 或换一个会跟重定向的抓取器；本沙箱演示用的是本地语料插口
  `_t/serve/corpus/`（任意抓取器都能往这里丢文件）；
- 需求目前限“单整数入参”这一类（包装器只处理 `long f(long)` / `const char *f(long)`），
  数组/字符串入参的包装还没做；
- 验证层用的是**示例 + 3 类性质**，性质库还很小（range/yesno/稳定性），覆盖不到更细的语义。

### 9.40 给自服务训练装闸门：发现它会把旧能力打坏，并修掉一批潜伏的回归（2026-11-13）

给 `selfserve` 加了两个安全件：

| 件 | 作用 |
|---|---|
| `--sentinels` | 每次入库前后跑 blind19/20/21 的哨兵，掉分就回滚这一次入库 |
| `--gate` | 训练结束跑**能力门**（隐藏组 + blind11..21），FAIL 就整体回滚到训练前模型 |

**结果（重要，且不好看）**：14 条需求训练后自身 14/14，但

```
能力门：训练后的模型跑隐藏组 + blind11..21
  [FAIL] hidden 通过 321 < 基线 328
  [FAIL] hidden 答错 7 > 基线 0
  能力门 FAIL ⇒ 已回滚到训练前的模型
```

**训练会把旧能力打坏 7 条**，而基于 blind 的哨兵**没抓到**（因为坏的是隐藏组）。结论：
自服务训练目前**不安全**，必须有 `--gate`，且哨兵应改成隐藏组抽样。

顺带查出一个**潜伏回归**（不是这轮引入的）：

- `运算:数组降序` 带 `输出 打印:空格数组`，被多条“从大到小…再求X”的描述抢先打印 → 一整组 2/8；
  修法：把 `数组降序` 改成**静默排序**（不打印），打印交给下一个算子或 `数组降序输出概念`；
- 给 `数组降序输出概念` 补精确排除词：`再/其中/逗号/逐行/平方/之和/总和/数组的和/每列`；
- `{加起来|相加|求和|总和|之和|加起来是多少}` 有 **6 个分支**，而模式展开上限是 **4** ⇒ “之和”被静默丢掉；
  拆成两条关键词后恢复（这条坑写进 §6.820 的限制说明）；
- `运算:回文判断2` 抢了“是回文数输出 1/0” ⇒ 加排除 `整数 / 回文数`。

**修复后**：隐藏组 **328/328**、`PASS capbench`（无组低于基线）、整包见 9.41。

`sqrt_sum` / `second_small`。修后 `平方根之和` 正确采纳了 `sqrt_sum`；但 `数组次小值` 仍被
`second_max` 蒙过去（两者在 [5,1,3] 上同解），说明**示例+性质永远可能被碰巧对蒙混**——
这正是“第二个问题”没法彻底解决的证据，只能靠更多示例/更强性质收敛。


### 9.44 试做“参数化概念算子”（第 k 小 / 左移 k 位）：被链式多命中卡死，回退（2026-11-13）

思路：迁移=0 的根因是“一条知识只认一句说法”。若把知识写成**参数化的概念**（`第<P>小`、`左移<P>位`），
那么 `第二小`/`第三小`、`左移两位`/`右移三位` 都该命中同一条知识——这是关键词架构里唯一可能产生迁移的做法。

实现了两处解析扩展（都已回退，未发布）：

| 扩展 | 作用 |
|---|---|
| 参数可从**匹配片段内部**取（中文数字） | `第[三]小` 里的 三 能变成 `<P>=3` |
| 参数可从关键词**正后面**取（中文数字） | `左移[两]位` 能变成 `<P>=2` |

**结果：失败。** 原因不是解析，是**匹配层**：

```
[chain] 命中 运算:第N个 @63
[chain] 命中 运算:区间元素和 @63
[chain] 命中 运算:区间元素最大 @63
[chain] 命中 运算:区间元素最小 @63
[chain] 命中 运算:第k小 @63     ← 5 个算子同时命中
链式要求 ≥2 个算子 ⇒ 拼出 5 个互不相容的算子 ⇒ 链路直接失败
```

`第`/`小` 在关键词空间里天然歧义：`第N个`、`区间元素*` 都用 `第` 当关键词。试过给它们加 `排除 小/大`、
`要求 到`，都没能在链路阶段把它们挡住（排除词只在候选层生效，链阶段仍是“多命中就拼”）。

**结论**：在“关键词子串匹配 + 链式拼装”的架构里，参数化概念会被同名关键词搅成多命中，
**迁移这条路在架构层面走不通**（这是第 4 次独立验证：自举迁移=0、砍关键词被能力门打回、
blind21→blind22 迁移=0、参数化概念被多命中卡死）。已全部回退，仓库状态与 `15108c0` 一致。


### 9.45 **方案 A 成功：双实例反统一 ⇒ 没教过的参数也能用（迁移首次非零）**（2026-11-13）

前面 4 次迁移实验都是 0（自举、砍关键词、blind21→blind22、参数化概念被多命中卡死）。这轮换成
**双实例反统一**（anti-unification）：不手工写参数化知识，让系统从两条“只差一个常数”的实例里自己归纳。

```
教：第二小 → { ...; x = (m >= 2) ? u[1] : ...; }
教：第三小 → { ...; x = (m >= 3) ? u[2] : ...; }
归纳：常量位置逐个对齐 ⇒ offset = k − 常量；结果：x = (m >= <P>) ? u[<P> - 1] : ...;
```

`tools/generalize.py` 做四件事：分组（同模板 + 语句挖掉数字后同形）→ 归纳（常量位置换 `<P>-offset`）→
生成关键词模式（中文数字枚举，**每 4 个一组**，因为模式展开上限是 4）→ 两级验证。

**实测（`tests/codegeneral.sh`，仓库模型不动，实例灌进副本）**：

| 项 | 结果 |
|---|---|
| 归纳 | 找到 `[第2小, 第3小]` ⇒ `概念_第{一|二|三|四}小`（另两组模式覆盖 五~十）|
| 教过的 k=2 / k=3 复现 | **OK**（与两条实例在随机输入上逐字一致）|
| **没教过的 k=5（第五小）** | **6/6** ← 本项目第一次测到非零迁移 |

生成的程序（第五小，输入 `5 1 3 2 4`）：`x = (m >= 5) ? u[5 - 1] : ...` → 输出 **5** ✓。

**边界（照实说）**：

- 只归纳“同模板、同一语句形状、常量随 k 等差”的实例对，别的形状不猜；
- 迁移维度是**数值参数**（k），不是“任意语义”；换族（如 进制、移位）还没试；
- 归纳出的概念还没有自动进主图（`concept_k.triples` 只给测试副本用），要不要入库是产品决定。

### 9.83 一轮“全线失败”的实验记录（§6.857–§6.859，全部回退）（2026-11-14）

| 尝试 | 想解决 | 实测结果 |
|---|---|---|
| 打印型去重算子关键词收窄（`去重` → `去重降序`）| `去重后求和` 被打印型链抢 | 无效（链仍选打印算子）|
| `数组最大/最小` 加 `最大值/最小值` 关键词 | `去重后最大` 拒答 | 隐藏组掉（`最值平均` 一族）|
