# 方案：先自学，再泛化/迁移，再扩图，最后扩语言

> 这份文档回答两件事：**为什么**按这个顺序做，以及做完之后 TlndebrSeek 能不能
> **说出自己为什么这么干**、**主动去搜/主动问为什么**。不是又一份“能力清单”。

## 0. 一句话结论

- 现在的内核会“按登记过的任务拼链”，不会“没见过的题自己想办法”；
- 所以顺序必须是 **自学 → 泛化/迁移 → 扩图 → 扩语言**：
  - 先有“不会 → 自己提出办法 → 用编译器/测试证明 → 才学会”的闭环（自学）；
  - 再量“学会一个，能不能用在没见过的变体/相邻任务上”（泛化/迁移）；
  - 有验证过的数据，扩图才不是囤垃圾（扩图）；
  - 最后把同一套闭环套到第二门语言上（扩语言）。
- 每一步都必须带**理由与证据**，否则“学会”不算数——这就是“知道为什么”的落地方式。

## 1. 现状诊断（用仓库里的数）

| 事实 | 数 | 含义 |
|---|---|---|
| C 任务模板 | 52 个 | 只覆盖“登记过”的题型 |
| 代码知识三元组 | ~111 万 | 多为语料/API 抽取，不等于“会写” |
| 泛化基准 blind50 首跑 | **2/8**（refuse 1 / wrong 5） | 换个算法组合就崩；**wrong 比 refuse 多**说明它会自信地拼错 |
| 理由层 | 无 | 它不知道“为什么选这条链/为什么失败”，只能说结果 |
| 自学闭环 | 无 | 失败就失败，不会把失败变成下一次的候选 |
| 教师通道 | 有（默认关） | 会先搜索再问大模型，但只显示、不进图 |

结论：**先修“为什么”和“自学”，别先扩图**。没有理由的 10M 条边只会让错误更难查。

## 2. 设计原则（不满足就不算完成）

1. **白箱**：每个结论都要能指回三元组/边，不能有“黑盒答案”。
2. **可验证**：代码用 `gcc` + 自测 + gold；自然语言用“能否被图/例子支持”判定，
   无法判定的进**待证**，不进事实层。
3. **教师只做冷启动**：大模型/搜索给的是候选与理由，不是知识；必须过验证 + 记录理由才收。
4. **失败也要记账**：失败原因同样是知识（`失败:*`），避免同一坑反复踩。
5. **默认关、离线可测**：外部调用只在显式开关下发生，门禁不联网。
6. **每轮一条结构改动**：新盲测集首跑读数、门禁全绿、攒批推送——沿用现有纪律。

## 3. “知道为什么”：理由层（新增，最先做）

### 3.1 数据形状

新增四类三元组（与现有 `任务/配方/运算/片段` 并列）：

```
目标:写排序工具        意图    用 C 读一行整数排序后输出
配方:排序加一          理由    先排序再加一，保证顺序稳定
片段:cmp_long          理由    比较器要严格弱序，否则 qsort 行为未定义
失败:中位数-最大值链   原因    把“中位数”错配成“最大值”，缺中位数算子
证据:blinds50-素数和   命令    gcc 编译 + 3 组随机输入全过
```

- `理由` 回答“为什么这样做”；`原因` 回答“为什么错”；`证据` 指向可复现命令/读数。
- 每条被接受的配方/片段/规则，**必须**带一条 `理由` 和一条 `证据`；
  缺任何一条只能停在待证区（`失败`/`待证`），不能进主图。

### 3.2 行为变化

- 合成/计划/学习时，输出里带“**依据**”：用了哪条任务、哪条配方、哪条理由、哪次证据。
- 新增一个“问为什么”的入口（命令名实现时再注册，避免文档指空）：
  输入一个目标/结论，回答“为什么信它” → 列出理由 + 证据；没有就直说“没有理由，不敢信”。
- 理由层不参与“会不会”的判定，只参与“**敢不敢用**”的判定：
  没有理由/证据的链，合成器可以提出，但不许落盘。

## 4. “主动搜、主动问为什么”：好奇心队列

### 4.1 触发条件（都可判定）

- 合成失败（没匹配 / 编译不过 / 自测红 / gold 不符）；
- 同一条描述两次走了不同链（低置信）；
- 图里出现冲突（两个理由互斥 / 证据过期）；
- 用户问“为什么”。

### 4.2 问题生成（把“不会”变成“具体的问题”）

不是笼统“这题怎么做”，而是：

- “为什么 `中位数` 被拼成 `最大值`？”（错配原因）
- “为什么这条链在 shape=matrix 上不成立？”（迁移边界）
- “为什么这个说法只在 blind50 的 2 题上对？”（泛化缺口）

### 4.3 处理顺序（沿用已发布的升级链路）

1. 本地检索：图里有没有现成理由/证据；
2. 搜索：`::ask` 的搜索段（默认关，联网才走）；
3. 问 DeepSeek：教师给候选理由；**只进待证 + 记“为什么问”**；
4. 人去确认，或机器验证（编译/gold）通过后转正。

限流：同一问题 24h 内只问一次；每天外部调用有上限；成本与失败都记账。

## 5. 自学闭环（第一步，先于泛化）

```
propose → verify → accept/reject → 记理由/失败 → 下一轮候选
```

- **propose 三个来源**：
  1. 组合已有配方/算子（不引入新东西）；
  2. 从成功/失败例子里归纳（现有 `induce` 能力的扩展）；
  3. 教师冷启动（DeepSeek 写一版，只当候选）。
- **verify（唯一的裁判）**：
  - C：`gcc` 编译 + 自测 + 随机输入 gold（blind 判官已有的机制）；
  - 自然语言：能否被图/例子支持；不能就进待证。
- **accept 条件**：验证通过 + 有理由 + 有证据 + 去重；否则 reject 并把原因写进 `失败`。
- **度量**：
  - 首跑盲测通过率（每轮新建，不调参）；
  - **teacher-free 通过率**（关掉教师后还能做多少）——这是“自学”是否真的发生的唯一证据；
  - 误收率（accept 了但后来被证伪的比例）；
  - 教师调用次数与成本。
- **反污染**：教师答案不直接进图；错误链只记失败原因，不重复重试同一失败。

## 6. 泛化/迁移（第二步）

- **按族切分**：训练族与测试族不重叠；同义改写单独一集；
- **迁移测试**：只学 A，直接考结构相邻的 B（例如学“去重后最大”考“去重后中位数”）；
- **跨形状迁移**：arr 上学会的链，matrix/file 上还成不成立；
- **读数**：每轮新建盲测集首跑；泛化读数与 teacher-free 读数一起报，禁止只报好看的。

## 7. 扩图（第三步，验证过的 2.5B；验证用 c7b2 分片放机械硬盘）

### 7.1 目标与容量（按仓库里已有的分片格式算）

- 目标改为 **2.5B 条验证过的边**（用户定的上限），不再追 7B；
- 存储用现成的 `.c7b2` 分片格式（`tools/c7b2_writer.h` + `tools/triples2c7b.c`）；
  **实测体积**（不是估的）：API/代码事实样本 **43–64 字节/边**（名字长的知识更贵，
  `capi.triples` 18 万条 → 7.7 MB = 42.9 B/边；2000 条样本 64 B/边）；
  2.5B 边按 43 B/边 ≈ **107 GB**，按 64 B/边 ≈ **160 GB** —— 机械硬盘要留 ≥200 GB；
  分片默认 500 万边/个 ⇒ **约 500 个分片**；
- 内存只做**热层**：现有 1000 万边以内的 in-memory 图保留作检索热层，
  冷数据按需读分片（mmap/顺序读），不把 2.5B 全塞进 15GB 内存；
- 数据来源：`tools/src_harvest.sh`（Debian/Ubuntu 源码 → 事实，实测 2,182 条/MB ≈ 54 B/条文本），
  流式“下载 → 抽事实 → 记一行账 → 删源码”，断点续跑；
- 2.5B 边的源码量 ≈ **1.15 TB**，按 3 MB/s 约 **4.4 天**连续抓取（不含验证）；
  7B 原方案 ≈ 3,133 GB / 12.4 天——这就是为什么先定 2.5B。

### 7.2 “基本全部有用”怎么量（2.5B 不可能逐条编译）

- **来源可追溯**：每条边带 包名 + 文件 + 抽取器版本；
- **分层抽样验证**：按包/语言/关系分层抽 1%（≈2500 万条）做编译/解析校验，
  有效率 ≥95%；抽样脚本与固定种子一起入库，可复现；
- **去重率**：同一 (主, 关系, 客) 重复率 <5%；
- **检索命中**：在代码任务盲测集上，热层 + 分片联查的召回率不退化；
- **延迟预算**：单次分片查询 p95 ≤ 50 ms（SSD 热层）/ ≤ 200 ms（HDD 冷层）；
  实测单分片（100 万边/20 万节点）p95 0.77 ms，但 **500 个分片必须先建“名字→分片”全局路由**，
  否则逐分片线性扫描会到秒级（§6.931）。

### 7.3 分阶段（每阶段都要过 7.2 的门）

| 阶段 | 规模 | 形态 | 验收 |
|---|---|---|---|
| S1 | 10M | 内存热层 | 抽检 ≥95%、延迟不退化 |
| S2 | 100M | 热层 + 分片 | 召回不退化、p95 ≤ 50 ms |
| S3 | 500M | 分片为主 | 抽检 ≥95%、断点续跑可恢复 |
| S4 | **2.5B** | HDD 分片 | 抽检 ≥95%、p95 ≤ 200 ms、去重 <5% |

### 7.4 风险

- **抓取配额/带宽**：4.4 天只是抓取；中途要能停、能续、能删源码；
- **硬盘健康**：2.5B 写入 + 抽样读取对机械盘是长期压力，先做 S2/S3 的 IO 压测；
- **污染**：语料抽取只能进待证；只有验证过的才进“有用”统计；
- **7B 的旧结论**：边本身能放硬盘（70–84 GB），真正的瓶颈是“验证 + 查询延迟 + 去重”，
  2.5B 已足够覆盖主流语言的高频代码事实。

## 8. 扩语言（第四步，Python 20 题）

- 新增 emit 后端（C 之外的第二目标语言），复用：任务/配方/理由层、验证闭环、盲测纪律；
- 先做 20 题最小闭环：读入一行 → 变换 → 输出，形状与 C 的 arr/str/two 对齐；
- 验收：`tests/` 里 Python 子集全绿 + 教师关掉后的通过率 + 新盲测首跑读数；
- 语言知识（函数名/语义）同样走“理由 + 证据”，不硬编码模板。

## 9. 下沉（第五步，加在“扩语言”之后）：机制归位，不滥用硬编码

扩语言会把“哪些机制是通用的、哪些只是 C 的方言”暴露出来；**先扩语言再下沉**，
避免把还没稳定的抽象冻进图里。下沉不是“再写一堆表”，而是给每个机制找**它该待的层**：

### 9.1 三层判据

| 层 | 放什么 | 判据 | 例子 |
|---|---|---|---|
| **图（数据）** | 事实、规则、同义改写、任务模板、算子关键词、关系定义 | 改一条数据就能改变行为；与语言无关；可消融 | `改写:先排好 改写 排序后`、`任务:* 关键词 *` |
| **元认知（策略数据）** | 何时搜索/追问/放弃、置信阈值、预算与限流、证据标准、失败归因策略、好奇心优先级 | 它约束“怎么想”，不直接给答案；改了会改变读数 | “证据必须含编译+测试”“同一问题 24h 只问一次” |
| **原语（代码）** | IO、图读写、编译/执行、安全门、调度循环、解析器 | 不可再降；删了系统不成立 | `code_test_file`、`action_run`、`::net` 白名单 |

**硬编码红线**：新增“语义表/策略表”之前，先问它属于哪层；能在图/元认知里表达的，
不许写进 C。确需写死的，必须同时给出：①为什么不能下沉；②消融测试（删掉/改数据后行为可见变化）；
③白名单登记。没有这三样，评审直接拒。

### 9.2 已经能看出来的下沉候选（本轮只登记，不搬）

| 候选 | 现在在哪 | 该去哪 |
|---|---|---|
| 中文数字解析表（一..九、十、X十Y） | `code.h` 里写死 | 图：`数字:十六 值 16` 之类；解析器留代码 |
| 停用词/虚词/领域词表（`S[]`/`W[]`/`ws[]`/`wa[]`） | `code.h` 静态数组 | 图：`词 --[虚词]--> 1`（虚词已经是数据，其余照此办理） |
| 数值/形状/输出格式的默认策略 | 散落在 C 的分支里 | 元认知：`元:输出格式 默认 …` + 策略引擎 |
| 搜索/追问/放弃的阈值与预算 | 常量/开关默认值 | 元认知：`元:追问 预算 每天 N`、`元:放弃 阈值 …` |
| 关系表（属于/有/会…的独占性） | `rel.h` 核心表 | 暂留原语（图的自举需要它），但**参数**（独占/多值）可下沉成数据 |

### 9.3 里程碑

| 阶段 | 交付 | 验收 |
|---|---|---|
| M6-1 | 硬编码清单：扫描 C 里的语义/策略表，逐条标 图/元认知/原语 | 清单入库；每条有理由 |
| M6-2 | 图下沉第一批（数字表、停用词、领域词） | 消融测试：删表 → 行为改变；gate 绿 |
| M6-3 | 元认知层最小引擎（预算/阈值/证据标准可配） | 改策略数据 → 读数可见变化；默认值不变 |
| M6-4 | 红线检查进 gate（新增硬编码必须登记+消融） | 无“黑户”语义表；gate 124+ 套绿 |

**为什么这条放在扩语言之后**：语言一变，才发现哪些表是“语言无关的语义”、哪些是“C 的实现细节”；
先下沉会把偶然当必然。但**元认知**部分可以提前做（它和语言无关），M6-3 允许与扩语言并行。

## 10. 风险与护栏

- **污染**：外部答案默认待证；无证据不落盘；失败原因单独记。
- **自信地错**：blind50 的 wrong 比 refuse 多——先做“合成后必须过 gold 才落盘”。
- **成本**：教师调用限流 + 记账；同一问题不重复问。
- **密钥**：只放 `.gitignore` 的 `tool.txt` 或临时环境变量；文档/日志/提交里不出现。
- **不可复现**：联网/教师参与的结果不直接进 gate，只做研究读数；gate 保持离线可跑。

## 11. 这个方案为什么能回答“为什么这么干”

- 每一步都要求写出**理由与证据**，理由本身也是图里的数据；AI 回答“为什么”时不是编，
  而是查理由层；查不到就说“没有理由”。
- 顺序不是偏好，而是依赖：没有自学闭环，扩图只会放大错误；没有泛化读数，
  自学是否真的发生无法判断；没有验证过的知识，扩语言只是再抄一遍模板。
